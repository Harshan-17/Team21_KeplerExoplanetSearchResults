# Kepler Exoplanet Analysis Platform

## Problem statement

The Kepler catalog contains thousands of records and many technical parameters. Searching those records manually, understanding what each value means, and comparing objects can be difficult, especially for someone with little astronomy background.

## Proposed solution

This project provides a small Streamlit application for searching and exploring Kepler objects. It brings together:

- planet properties
- host-star properties
- transit information
- the existing ML classification workflow
- screening priority for further review
- expected next-transit timing
- existing visual analysis
- plain-language explanations
- a deterministic **ASK KEPLER** chatbot for supported searches and questions

## Main features

- **Overview**: explains the workflow and shows counts calculated from the cleaned catalog.
- **Explore catalog**: searches identification fields and filters recorded radius, period, and classification values.
- **Candidate analysis**: shows the selected object's identification, planet, host-star, and transit values.
- **Next Transit Countdown**: calculates the next expected transit from the selected object's catalog timing fields.
- **ML classification**: shows the existing Logistic Regression and Random Forest outputs and probabilities when the required values are available.
- **Screening**: shows saved project screening scores and indicators for further review.
- **Visualizations**: organizes the useful graphs already generated by the project.
- **ASK KEPLER**: supports a small set of natural-language searches and questions using the actual dataframe and existing project results.

## Next transit

The application calculates the next expected transit mathematically using the catalog transit epoch and orbital period:

```text
next_transit = epoch + n × orbital_period
```

The application fields are:

- `transit_epoch_bkjd` (mapped from the source field `koi_time0bk`)
- `orbital_period_days` (mapped from the source field `koi_period`)

The current UTC time is converted to the same BKJD time basis before the next future event is selected. The result is a mathematical expected-transit timing estimate, not an ML prediction. It does not scientifically confirm an exoplanet.

For this helper, BKJD is treated as the Kepler time basis `BJD - 2454833.0`.

## Machine learning

The application reuses the existing project workflow in `src/ml.py`. It uses Logistic Regression and Random Forest to classify objects according to the available cleaned-dataset labels:

- `CONFIRMED`
- `CANDIDATE`
- `FALSE POSITIVE`

The models are dataset-based classifications. The application does not describe a model prediction as scientific validation or confirmation.

## Screening

The application reuses the existing screening implementation and saved table in `results/tables/kepler_screening_results.csv`. Screening priority helps identify objects for further review. It is not scientific confirmation.

## Dataset

The application uses the repository dataset at:

```text
data/raw/processed/kepler_cleaned.csv
```

The current cleaned file contains **9,201 rows and 48 columns**. Its normalized fields include identification, classification, planet, host-star, transit, timing, and screening-related values. The application reads the file at runtime rather than hardcoding catalog counts.

## How to run

From the repository root, install the project dependencies:

```bash
python -m pip install -r requirements.txt
```

Start the application with:

```bash
streamlit run app/streamlit_app.py
```

## Limitations

- ML predictions are dataset-based classifications.
- Screening is a prioritization aid for further review.
- Next transit is a mathematical timing estimate.
- The application does not scientifically validate exoplanets.
- Full light-curve time-series analysis is not available in the application.
