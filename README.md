# EXOINSIGHT — Kepler Exoplanet Discovery & Analysis

EXOINSIGHT is an interactive Streamlit prototype for exploring the capstone team's processed NASA Kepler KOI catalog. It includes an overview dashboard, searchable observation explorer, planet and host-star analysis, advanced feature visualizations, and a clearly labeled classification demonstration.

## Run locally

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS / Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run streamlit_app.py
```

The app reads `data/raw/processed/Data_cleaned.csv` and optionally displays the model comparison and candidate prediction artifacts under `member 2/`.

## Pages

- **Overview** — catalog counts, disposition mix, parameter scatter, and data-derived descriptive summaries.
- **Data Explorer** — search by KOI, planet name, or host ID; filter disposition, release, radius, period, and transit depth; inspect a selected record.
- **Exoplanet Analysis** — filtered radius and period distributions, plus radius/period and transit-depth/radius relationships.
- **Host Star Analysis** — search host systems and inspect their observations and stellar properties.
- **ML Prediction** — selected-object screening output from the existing Logistic Regression and Random Forest work, alongside the team's saved model metrics and candidate prediction artifact.
- **ASK KEPLER** — a small natural-language interface for catalog filters, selected-object facts, transit timing, model results, and screening.
- **Advanced Visualizations** — choose scatter plot axes and color grouping; inspect a correlation matrix.
- **About Project** — project modules, data flow, and provenance.

## Data and interpretation

The dashboard uses the bundled processed CSV. Counts, plots, and descriptive insights are calculated from those rows. Catalog dispositions come from the source data; they are not generated by the dashboard. The existing classification work separates `CONFIRMED` and `FALSE POSITIVE` objects; `CANDIDATE` remains the catalog label rather than a third trained model class. Because the repository does not include serialized model files, the application fits the notebook-equivalent estimators once per process from the prepared training split and reuses them across interactions.

Charts use the source columns (`koi_prad`, `koi_period`, `koi_depth`, `koi_steff`, `koi_srad`, and related fields); the interface labels include units for readability. Plot distributions and summary statistics should be interpreted as descriptions of this processed catalog, not as claims about all exoplanets.

## Project package

- `data/` — raw and processed catalog files and data preparation metadata.
- `kepler_Package/` — reusable analysis functions under development.
- `member 2/` — classification evaluation and candidate prediction outputs.
- `notebooks/` — project preparation, classification, and planet analysis notebooks.
- `reports/` — preparation, validation, host-star, and outlier reports.
